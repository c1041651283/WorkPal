# WorkPal v1.2.1：锁屏/唤醒后的代理恢复

## 查到的证据

用户确认唤醒后 FortiClient 显示 VPN 已断开。运行日志中，11:57–12:34 多次出现网卡状态读取失败；旧检查使用 CIM/WMI，查询失败只能进入 unknown。日志显示当时守护间隔为 300 秒。旧版本没有唤醒/解锁通知，守护运行时也禁用了在家连接入口。

未捕获实际锁屏断线全过程，无法仅凭这些日志确定 FortiClient 断开的原因；本次修复的是 WorkPal 的检测、状态更新和重新连接入口。

## 修改

- 代理守护改用 Windows IP Helper 读取网卡描述、状态与地址；TCP 探测失败不再抹掉已读取的网卡状态。
- 菜单刷新也不调用 WMI/netsh，避免更新菜单时再次阻塞守护。
- 解锁/唤醒会唤醒正在运行的守护：立即检查，最多再进行两次间隔 5 秒的复查，然后回到原先的 1/2/5 分钟间隔。守护关闭时不会被唤醒事件自动开启。
- 显示最近检查时间，区分 VPN 断开、公司代理不可达与状态读取失败。
- 在家模式下，虚拟网卡仍显示已连接但公司代理连续三次不可达时，临时关闭系统代理；不把它误报成已确认 VPN 断开。
- “在家连接 / 重新连接公司”在守护运行期间也可使用，沿用当前会话的原始备份。用户主动点击时，公司网络不可用就临时关闭系统代理并打开 FortiClient；不需要恢复旧代理。
- 不操作 FortiClient 登录、断开、配置、账号、证书、路由、DNS 或网卡，不阻止正常锁屏或休眠。

## 使用

退出旧版后，运行 `dist/proxy-resume-20260920/WorkPal/WorkPal.exe`。

需要重新登录时，右键托盘 → 代理守护 → 在家连接 / 重新连接公司。自行在 FortiClient 中完成登录/验证码；若不想等待定时检查，登录后点击“立即检查并修复一次”。
