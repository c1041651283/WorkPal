# 代理自动切换排查（2026-09-20）

## 已确认的证据

- 用户组策略结果中，`GPO_PSH_USER_Proxy-Policy` 已启用且实际应用。
- 该策略的注册表首选项以 Update 方式设置 `HKCU\Software\Microsoft\Windows\CurrentVersion\Internet Settings\AutoConfigURL`。
- 值为 `http://proxy.psh.com.cn/proxy-psh1.pac`，RSoP 记录执行成功。
- 已只读核对这份策略的 SYSVOL Registry.xml：它包含上述 AutoConfigURL 项，未发现该文件中另有 ProxyEnable 项，也未配置仅应用一次。
- 检查时 Windows 为手动代理开启、系统 PAC 关闭；VPN 网卡已连接，公司代理端口可达。
- WorkPal 新版进程仍运行，但代理助手当时没有持有接管锁。当前存在的恢复备份中，原设置为 PAC 开启、手动代理关闭。
- 50 秒只读观察期间没有出现开关变化。此次未捕获用户所说的那次实际改写，不能确定关闭手动代理的具体进程。

## 判断

公司组策略是已经证实的 PAC 地址下发来源。组策略首选项默认会在策略刷新时重新应用，因此只在 Windows 设置中关闭脚本，不能保证长期保持。

不能仅凭这一条 AutoConfigURL 项，断言它也直接写入了 ProxyEnable=0。WorkPal 恢复旧设置、FortiClient、网络认证软件是否参与实际开关变化，还需按发生时间核对，或用 Process Monitor 捕获相关注册表写入。

此外，WorkPal 目前用原始字符串比较代理设置：`proxy.ricoh.co.jp:8080` 和 `http://proxy.ricoh.co.jp:8080` 会被当成不同设置。这可能导致助手停止接管，但不能据此认定它是 PAC 自动开启的来源。

## 建议方案

1. 优先请 IT 为该用户/电脑调整这条代理首选项的适用范围，或评估“仅应用一次”。目标是允许系统固定代理与浏览器独立 PAC 并存。
2. 若公司要求持续下发系统 PAC，则保持系统 PAC，对需要固定代理且支持独立配置的软件，分别配置 `proxy.ricoh.co.jp:8080`。不支持独立配置的软件需要 IT 协调。
3. WorkPal 后续应补充代理变更日志、等价代理地址比较，并将“停止监视”和“恢复旧设置”明确区分。不要在未确定策略要求时添加无限循环抢写。

## 可转给 IT 的说明

本机应用的 `GPO_PSH_USER_Proxy-Policy` 会更新用户 Internet Settings 的 AutoConfigURL 为 `http://proxy.psh.com.cn/proxy-psh1.pac`。工作需要同时使用系统固定代理 `proxy.ricoh.co.jp:8080` 与 Edge 独立 PAC，但系统设置会在正常使用中恢复成脚本模式。请确认是否可针对该账号/电脑调整此首选项的作用范围或改为仅应用一次，并核对是否还有其他组件关闭 ProxyEnable。

本次只做诊断，没有修改系统代理、公司策略、FortiClient 配置或 VPN 连接。
